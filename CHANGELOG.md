## [Unreleased]

### Changed
- **DuckDB 2.0.1 minimum and Python 3.14 engine clients (#417)**: the minimum supported DuckDB version is now **2.0.1**: the `duckdb` extra requires `duckdb>=2.0.1`, the dev dependency group pins `duckdb==2.0.1`, and both install on Python 3.14 from the abi3 wheels. The `< 3.14` markers are gone from the `duckdb`, `age`/`psycopg[binary]`, `falkordb` and `neomodel` dependencies because their current releases support 3.14. DuckDB 2.0 only parses `CREATE PROPERTY GRAPH` and `GRAPH_TABLE` after the per-connection `SET active_grammar_extensions = ['duckpgq'];` opt-in, so `DuckDbBridge.ensure_duckpgq()` now runs it after `LOAD duckpgq;` (including when the caller already loaded the extension), and the embedded DuckPGQ tests, PGQ conformance corpus and live harnesses do the same.

### Fixed
- **PostgreSQL JSON parameter encoding, native and bridge (#421)**: Python dicts and `voyager_ogm.Json(...)` values bind as `jsonb` on the native driver and `PostgresBridge`. Lists keep the array behaviour psycopg has: lists of scalars stay typed SQL arrays, a list of dicts becomes `jsonb[]` (one JSON element per dict), and nested lists become multidimensional arrays. A placeholder explicitly cast to `json`/`jsonb` (for example `$v::jsonb`) binds any list as one JSON document, so an empty list becomes `[]` and never the JSON object `{}`; without such a cast an empty list remains an empty SQL array literal for array-typed slots. `Json(...)` is the escape hatch for forcing JSON in any context, including JSON `null`, scalar lists and ragged nested lists, and is unwrapped for AGE, Bolt, FalkorDB and DuckDB. The value conformance pack no longer records the PostgreSQL JSON parameter differences.
- **Float precision through JSON text (#422)**: `serde_json` now parses with `float_roundtrip`, so native PostgreSQL `jsonb` results and Apache AGE `agtype` parameters, results and nested list/map values round-trip `f64` exactly (including subnormal values and `1.7976931348623157e+308`). Non-finite JSON numbers written inside containers are emitted as `NaN`/`Infinity`/`-Infinity`, and reading accepts those tokens plus out-of-range numeric literals (returning Python `inf`/`-inf`, like psycopg) instead of raising `number out of range`. The value conformance pack no longer records the PostgreSQL and Apache AGE float differences.
- **Bolt 5.x version range negotiation and 4.4 UTC fallback (#414)**: `BOLT_PROPOSED_VERSIONS` now proposes Bolt `5.4..=5.0` and `4.4..=4.2` ranges so Memgraph negotiates Bolt `5.2` (sending `HELLO` without `bolt_agent` for `5.1..=5.2` followed by `LOGON`) and uses UTC temporal tags (`0x49`/`0x69`), preserving `fold=1` DST instants and emitting typed `Timestamp` / `pl.Datetime` columns with timezones. Bolt `4.4` connections request `patch_bolt: ["utc"]` and keep the legacy `0x46`/`0x66` path when unpatched. Exposes negotiated protocol version on `AsyncConnection`, `NativeClient`, and `PyNativeClient.protocol_version_sync()`. Native Memgraph nodes and relationships now also carry `element_id` (a Bolt 5 field), matching the bridge.
- **Native Bolt spatial `Point` hydration and Arrow/Polars struct encoding (#419)**: **Breaking** for callers reading `dict` or JSON strings from native Bolt spatial columns: `Session.execute()` now hydrates `Point2D` and `Point3D` values (top-level and nested in lists, maps, nodes, relationships, and paths) to `voyager_ogm.Point` with SRID, and `execute_to_arrow()` / `execute_to_polars()` expose spatial columns (and `List<Point>`) as `Struct(srid: Int64, x: Float64, y: Float64, z: Float64)` with `voyager.type = "point"` metadata.
- **Legacy Bolt 4.4 zoned datetimes and negative duration component fidelity (#420)**: legacy `0x66` zoned datetimes now resolve local wall-clock time to UTC for Arrow/Polars `Timestamp` columns and include their resolved UTC offset in fallback/JSON ISO strings, `_hydrate_datetime` interprets offset-less bracketed zone strings in the named zone rather than UTC, and negative `Duration` values with `months == 0 && days == 0` route to `Struct(months, days, seconds, nanoseconds)` in Arrow/Polars to preserve exact server components (`days=0, nanoseconds=-1000`) instead of `timedelta` normalization.
- **Bolt and FalkorDB bridge parameter adaptation (#418)**: `Neo4jBoltBridge` (Neo4j and Memgraph) now converts offset-aware `datetime.time` values to `neo4j.time.Time` with a fixed offset, converts `zoneinfo.ZoneInfo` datetimes through `pytz` so the zone name and `fold` survive without crashing the `neo4j` 6.1 driver, and sends `uuid.UUID` parameters as strings; `FalkorDBBridge` also sends `uuid.UUID` as a string. These match the official clients and the native backend.
- **DuckDB bridge Duration, TIMETZ and JSON parameters (#423)**: `DuckDbBridge` now binds `voyager_ogm.Duration` as a DuckDB `INTERVAL` (preserving months, days and microseconds), sends negative-offset `datetime.time` values as `TIMETZ` text instead of failing in the eager binder, and serializes `dict`/`list` parameters cast to `JSON` so DuckDB no longer infers a `STRUCT` and coerces mixed lists such as `[1, True, None]` to `[1, 1, None]`.
- **DuckDB bridge Arrow/Polars value exports (#424)**: **Breaking** for callers reading DuckDB Arrow/Polars columns. `DuckDbBridge.execute_to_arrow()` now exports `HUGEINT` as `decimal128(38, 0)` instead of raising `OverflowError`, `UUID`/`UUID[]` as `fixed_size_binary(16)`/`list<fixed_size_binary(16)>` (Polars `Binary`) instead of strings, `TIMETZ` as ISO text tagged `voyager.type=time_tz` (Polars `String`) instead of a naive time, and `JSON` as UTF-8 text tagged `voyager.encoding=json`; `execute_to_polars()` uses the same conversion and `Session.transaction()` now uses the same Arrow path as auto-commit instead of returning raw UUID/JSON strings.

## [0.5.0-alpha.1] - 2026-11-27

First alpha of the 0.5 line. The theme is a portable query interchange format and the same values everywhere: Query Spec v1 with a JSON Schema, reference vectors and a conformance corpus, a working `voyager` CLI, live schema introspection, and native backends that return the same Python types as the bridges and the official clients.

Highlights of 0.5.0-alpha.1:
- **Query Spec v1**: a Rust consumer (#289) with a JSON Schema, reference vectors (#188), strict validation with `INVALID_SPEC` and a JSON Pointer (#187), a revision and compatibility policy (#292), and serialisation from the fluent API (#189).
- **Conformance corpus**: packs P0-P4 (#253-#258) run live on Neo4j, Memgraph, FalkorDB, Apache AGE and PostgreSQL 19 through three lanes, official clients, Voyager bridges and native (#297). A generated value conformance pack (#299) compares values and Python types across every path.
- **CLI v1**: `voyager doctor`, `compile`, `validate` and `introspect` (#119, #265), released as binaries for six targets, through `cargo binstall` and as the `voyager-cli` wheel, with `voy` as a short alias (#133).
- **Same values on every backend**: typed native parameters (#391) and stdlib result types with the new `voyager_ogm.Duration` (#395); `GraphNode`, `GraphRelationship` and `GraphPath` results (#372); decoded Apache AGE results (#353).
- **Models and schema**: field value constraints (#282), declarative relationship navigation (#121), model schema export (#125), table DDL for SQL/PGQ (#327).
- **TLS for the native drivers** (#219).

Breaking changes (details in the entries below):
- Result values: native backends return stdlib Python types and `Duration` instead of strings (#395); native PostgreSQL parameters are typed, so comparing a text column with a `UUID` or `datetime` parameter needs a cast (#391); Rust `QueryResult` is `#[non_exhaustive]`.
- Entities: whole nodes, relationships and paths come back as `GraphNode` / `GraphRelationship` / `GraphPath` on every engine (#372); Apache AGE results are decoded (#353) and a single whole entity is keyed by its variable (#285); AGE and SQL/PGQ column aliases keep their case (#377).
- Query Spec v1 is strict: one spelling per construct (#292), invalid, dropped or misattached clauses raise `INVALID_SPEC` (#187), and references the emission order cannot honour are rejected (#271).
- Fluent API: variable scope is checked before compiling (#287) and aggregations must sit in a projection (#272).
- Models: `Field` nullability is inferred from the type annotation (#332).
- SQL/PGQ property-graph DDL names tables and edge keys consistently (#325); SQL/PGQ on PostgreSQL is experimental (#373).
- The FalkorDB driver bridge honours the graph name from `graph_name=` or the URI (#339).

### Added
- **Value Conformance Pack (#299)**: a live, Hypothesis-generated differential test pack (`packages/python/tests/values/`) runs 19 value kinds through every engine (Neo4j, Memgraph, FalkorDB, Apache AGE, PostgreSQL 19, DuckDB) and compares value and Python type across the official client, the bridge, the native backend and native `execute_to_arrow()` / `execute_to_polars()`, as a parameter, stored as a property or column, nested in lists and maps, as node and relationship properties, and inside a transaction. `just values-live [engine] [--seed N] [--examples N] [--exploratory]` runs it (fixed seed by default, an opt-in exploratory profile), a failure prints a per-stage trace (Python value, Voyager parameter, wire encoding, server type, Arrow type, Python result), every run writes an engine x backend x value-kind matrix to `target/values-conformance/`, and `known_differences.json` records each accepted difference with a reason (and issue number for bugs); an entry that stops occurring fails the run. Adds the diagnostic `voyager_ogm._voyager_rs.inspect_native_wire()` and the `hypothesis` dev dependency.
- **Query Spec v1 Revisioning and Compatibility Policy (#292)**: Query Spec v1 now has a revision alongside its major version. Documents may carry an optional integer `spec_revision` (minimum 1) at the root and in nested specs; a missing or `null` value means revision 1, today's format. The Rust core is the source of truth through `voyager_ogm::spec::SPEC_VERSION` and `voyager_ogm::spec::SPEC_REVISION`, Python exposes `voyager_ogm.QUERY_SPEC_VERSION` / `voyager_ogm.QUERY_SPEC_REVISION`, and `voyager doctor` prints the supported `query spec: v1 revision 1`. A document that requires a newer revision is rejected with `INVALID_SPEC` at `/spec_revision` and a message naming the supported revision. `Query.to_spec_dict()` and `Expression.to_spec_dict()` now emit `spec_revision`, so exported documents are self-describing. The schema keeps its stable v1 `$id` and records the revision in a new `x-spec-revision` annotation; `spec/README.md` gains a "Compatibility and versioning" section covering the major + revision rule, what counts as an addition versus a break, the 1.0.0 guarantee (0.x may still break, with each change bumping the revision and listed as breaking), the pre-optimisation export guarantee, and the revision-bump checklist.
- **Multi-Platform CLI Release Binaries, `cargo-binstall` Metadata, and `voyager-cli` Python Wheel (#133)**: `.github/workflows/release.yml` now builds, smoke-tests, and attests standalone `voyager` archives (`voyager-cli-v<version>-<target>.tar.gz` / `.zip`) across six targets (`x86_64-unknown-linux-gnu`, static `x86_64-unknown-linux-musl` with rustls/ring, `aarch64-unknown-linux-gnu`, `aarch64-apple-darwin`, `x86_64-apple-darwin`, and `x86_64-pc-windows-msvc`), attaches them with `SHA256SUMS` and `actions/attest-build-provenance` provenance to the GitHub Release, adds `[package.metadata.binstall]` to `crates/voyager-cli/Cargo.toml` for `cargo binstall voyager-cli`, and builds/publishes the lockstep `voyager-cli` Python wheel (`packages/cli/pyproject.toml`, `bindings = "bin"`) wired into `voyager-ogm[cli]` and verified by `scripts/check_version_sync.py`. The Linux `-gnu` binaries are linked against glibc 2.28, the same baseline as the manylinux_2_28 wheels. The CLI is a single `voyager` binary: the archives add the short alias `voy` as a symlink (a `voy.cmd` shim on Windows), while `cargo install`, `cargo binstall` and the wheel install `voyager` only.
- **Live Corpus Voyager Lanes (#297)**: the live conformance corpus now runs each scenario through three lanes: `official` (today's engine clients and the AGE/SQL-PGQ `Session` reference path), `bridge` (`Session` over the Python bridges) and `native` (`Session(..., backend="native")` over `voyager-drivers` for Neo4j, Memgraph, FalkorDB, Apache AGE and PostgreSQL 19 SQL/PGQ). Fixtures load through the same official loaders, so only statement execution differs. `just corpus-live [engine] [lane]` selects one engine/lane or all, defaults to the previous `official`-only behaviour, and prints a per-lane/per-engine pass/fail/skip summary. Differences are compared structurally (scenario, lane, engine, column, expected, actual) against canonical `rows.json` values including node labels and relationship types. Reviewed differences live in `spec/corpus/known-lane-differences.json`; an unexplained difference fails, and an entry that no longer matches fails with "known lane difference is fixed, remove from ...". `spec/corpus/README.md` documents the lanes, the list and the commands.
- **Result Column Names on `ExecutionResult` (#378)**: `Session.execute()` and `AsyncSession.execute()` results (`ExecutionResult`, and `result.mappings()`) now expose a read-only `columns` property (`tuple[str, ...]`) and a `keys()` method (`list[str]`) in projection order, populated from driver metadata (Bolt `keys`, FalkorDB `header`, PostgreSQL/Apache AGE and DuckDB/Relate cursor `description`, and the native Arrow schema on `ArrowStream`) even when zero rows are returned, and empty for write statements without `RETURN`/`RETURNING`. `ExecutionResult.to_polars()`, `ExecutionResult.to_arrow()`, `Session.execute_to_polars()`, and `Session.execute_to_arrow()` (sync and async, bridge and native) now preserve those column names on empty results.
- **Reference Cypher Override for Recording Known-Diff Corpus Rows (#307)**: `scenario.json` now supports an optional `reference_cypher` object (`statement`, `reason`, and optional `params`), validated against `scenario.schema.json` and only allowed when `targets.cypher.status` is not `supported`. `just corpus-record-rows` runs `reference_cypher.statement` on Neo4j to reproduce `rows.json` and refuses to silently fall back to a `known-diff` compiled Cypher statement when `reference_cypher` is absent.
- **Relational Table DDL Generation for SQL/PGQ (#327)**: `SchemaManager.generate_table_ddl(*models, dialect="postgres"|"duckdb")` generates `CREATE TABLE IF NOT EXISTS` statements for vertex and edge tables using the #325 naming rule, endpoint foreign keys, dialect-specific type mapping, and surrogate primary keys on edge tables to allow parallel edges (or declared primary keys when defined). `SchemaManager.generate_pgq_schema_ddl(graph_name, *models, dialect="postgres"|"duckdb")` emits tables, sequences, constraints, indexes, and property-graph DDL in run order for PostgreSQL 19 and DuckPGQ.
- **Declarative Relationship Navigation on Node Models (#121)**: `RelationshipTo` and `RelationshipFrom` declare outgoing and incoming relationship attributes on `Node` models. Targets and optional relationship models accept classes or strings, string forward references (including circular model references) resolve on first use, and an unknown name raises a clear `LookupError`. Class access returns the descriptor; instance access returns a manager and never queries. The sync manager's `.all()` / `.filter(...)` and the `AsyncSession` manager's awaitable equivalents match the source by primary key, traverse in the declared direction, filter fluently, project one column per declared target property with stable aliases, and hydrate targets through the session identity map. Navigation therefore works on default native-client URI sessions as well as driver bridges across Neo4j, Memgraph, FalkorDB and Apache AGE, and on SQL/PGQ and embedded DuckPGQ property graphs. `.connect(target, properties=None)` and `.disconnect(target)` are staged in the session unit of work and written by `session.flush()` / `await session.flush()`, with same-source operations coalesced into one `UNWIND` batch; rollback discards them. The Rust core stores each declaration on `NodeSchema` (round-tripping through snapshot/restore and `export_schema` as a new `relationship_attributes` key without changing existing keys) and provides navigation, connect, disconnect and batched builders that use the existing multi-dialect emitters.
- **Query Spec v1 Label Predicate (#306)**: the expression `["label", variable, labels]` tests that a bound node or relationship has every listed label, so `["label", "i", ["TextNode"]]` compiles to openCypher and ISO GQL label tests and to Apache AGE's `label(i) = 'TextNode'`, while SQL:PGQ raises `UNSUPPORTED_FEATURE` (it has no label test in `WHERE`). Several labels mean all of them, like Cypher `i:A:B`. The fluent API gains `has_label("i", "TextNode")` and `ident("i").has_label("TextNode")`, and `Query.to_spec_dict()` round-trips the expression.
- **Query Spec v1 Pagination Parameters (#321)**: `skip`, `offset` and `limit` now accept `["param", name]` in addition to a non-negative integer, at the root and inside `WITH`. The fluent API accepts `param()` in `.skip()`/`.offset()`/`.limit()`, `Query.to_spec_dict()` keeps the parameter, and the four emitters produce `SKIP $name`/`LIMIT $name` (openCypher, Apache AGE), `OFFSET $name`/`LIMIT $name` (ISO GQL) and `LIMIT $name`/`OFFSET $name` (SQL/PGQ). Bound values are checked for a non-negative integer before dispatch, and malformed parameter arrays are `INVALID_SPEC` at their JSON Pointer. **Breaking** for Rust code that builds the AST directly: `ReturnClause` and `WithClause` `skip` and `limit` are now `Option<PaginationValue>` (`Count(u64)` or `Parameter(String)`) instead of `Option<u64>`.
- **TLS for the Native Drivers (#219)**: `voyager-drivers` now connects over TLS with rustls (ring provider, operating-system root store) behind a new `tls` Cargo feature, on by default in `voyager-drivers`, `voyager-cli` and the Python wheel. Bolt supports `bolt+s` / `neo4j+s` / `memgraph+s` (certificate and hostname verified) and `+ssc` (any certificate); Redis/FalkorDB supports `rediss`, `falkordbs` and `valkeys`; PostgreSQL and Apache AGE send an SSLRequest and follow libpq's `sslmode` (`disable`, `allow`, `prefer`, `require`, `verify-ca`, `verify-full`, with `sslrootcert`, `sslcert`, `sslkey` and `sslrootcert=system`), and only `prefer` continues in plaintext when the server answers `N`; `sslnegotiation=direct` (PostgreSQL 17+) starts TLS without an SSLRequest, using the ALPN protocol `postgresql`. URI parameters can strengthen the TLS a scheme or `sslmode` asks for but never weaken it: weakening, duplicate or contradictory TLS parameters (`bolt+s://…?tls=false`, `?sslmode=require&sslmode=disable`, `?sslmode=require&tls_ca_file=system`) are rejected, TLS parameter names are case-insensitive, and `tls_ca_file=system` implies `verify-full` like `sslrootcert=system`. A custom CA bundle, a client certificate and key for mutual TLS, and an SNI / hostname override (`tls_server_name`) are URI parameters for every protocol and `TlsOptions` on `ConnectionConfig`; `postgresql+ssc` / `age+ssc` and `?tls=insecure` are new. Without the `tls` feature a TLS URI still fails with an error naming the feature instead of downgrading to plaintext. `voyager doctor --uri` checks TLS endpoints and reports `over TLS`. `BoltConnection`'s default stream type is now `NetStream` (plain or TLS) instead of `TcpStream`. Malformed-URI errors and `ParsedUri`'s `Display` no longer show the user name and password, and a Redis/FalkorDB connection now fails when the server never answers `HELLO`. `containers/compose.tls.yaml` and `containers/tls/gen-certs.sh` provide a TLS test stack with a throwaway CA.
- **Field Value Constraints (#282)**: `Field` now supports optional client-side value constraints (`pattern`, `ge`, `gt`, `le`, `lt`, `min_length`, `max_length`, `choices`) validated on instance creation, attribute assignment, and save paths (`Node.save`, `Session.register`/`flush`), with declaration-time checks and `FieldConstraintError`.
- **Query Spec v1 Open Hop Bounds and SET Map Merge (#290)**: Query Spec v1 now supports open variable-length hop bounds (`*2..` via `max_hops: "unbounded"`) and map merge in SET mutations (`["set", variable, map_expression]`, e.g. `SET p += $map`), closing the last two fluent query features that raised `UNSUPPORTED_FEATURE` on `Query.to_spec_dict()`. Both constructs round-trip cleanly from fluent queries through `to_spec_dict()` to `compile_query_from_spec`, compiling to identical statements and parameters in every supporting dialect (Cypher, ISO GQL, Apache AGE, and SQL:PGQ where applicable). The v1 JSON Schema accepts `"unbounded"` for `max_hops` and the 3-element `set` mutation, `spec/README.md` documents both shapes, and new valid and invalid reference vectors cover both forms.
- **Working CLI v1 with `doctor`, `compile` and `validate` (#119)**: `voyager-cli` now compiles Query Spec v1 JSON documents through `voyager_ogm::spec::compile` and validates them through the same consumer, from a file or stdin (`-`). `compile` supports `cypher`, `age`, `iso_gql`, `sql_pgq` and `duck_pgq`, a text format that keeps stdout to the statement with parameters behind `--show-params`, and a JSON format with `statement`, `parameters`, `columns` and warnings. `validate` prints `<json-pointer>: <message> (<ERROR_CODE>)` and exits `1` on failure and is silent on success. `doctor` reports only build facts it can check, and with `--uri` connects through `voyager-drivers` and reports the protocol, server version, matching dialect and ping round-trip latency; passwords come from `--password-env` or the URI userinfo, and credentials are optional so servers without authentication (such as Memgraph and FalkorDB with auth disabled) need no username or password. Exit codes (`0` success, `1` invalid spec, `2` usage, `3` connection check, `4` input/output) are documented in every `--help` and the READMEs. The placeholder `bench` subcommand and the hard-coded diagnostic text are removed.
- **Live Schema Introspection and `voyager introspect` (#265)**: `voyager_drivers::introspect` (Rust) and `voyager_ogm.introspect_schema(uri | NativeClient | Session)` (Python) read a live database's labels, relationship types with endpoints, properties, constraints and indexes into the shape of `export_schema(models)`, plus `constraints`, `indexes` and `source` lists; keys a database cannot know (`model`, `description`, `attribute`, `has_default`, `constraints`, a node's `relationship_attributes`) are `null`. Supported engines are Neo4j 5.13+, Memgraph, FalkorDB and PostgreSQL 19 SQL/PGQ property graphs; property types and relationship endpoints come from type constraints or declared column types, otherwise from a bounded sample (`sample_size`, default 1000). Apache AGE and DuckDB raise `UNSUPPORTED_FEATURE`. The new `voyager introspect --uri <uri> [--format text|json] [--sample-size N]` prints the same JSON as the library and exits `5` for an unsupported engine.
- **Model Schema Export (#125)**: `export_schema(models)` returns a JSON-serialisable dict of node labels, relationship types with their declared endpoints, and per-property type, nullability, default, description, unique/index/primary-key flags and `Field` value constraints, built from the same registry entries as the DDL. `Node.to_json_schema()` and `Relationship.to_json_schema()` emit a JSON Schema draft 2020-12 document for one model, including descriptions, defaults and the value constraints.
- **Query Spec v1 Consumer in the Rust Core (#289)**: `voyager_ogm::spec` now exposes `build_query(&serde_json::Value) -> Result<QueryBuilder, SpecError>`, `build_nested_query`, and `compile(&Value, dialect, &SpecCompileOptions) -> Result<SpecCompileResult, SpecError>`, so Rust users, the CLI and other bindings can compile a Query Spec v1 document without going through Python. `SpecError` carries the same `ErrorCode`, JSON Pointer and message as before, and `SpecCompileResult` returns the non-fatal warnings. The query-builder, scope walker, alias checks, depth guard and error-path logic moved into `voyager-ogm` next to `spec_export`; the PyO3 `compile_query_from_spec` is now a thin Python-to-JSON wrapper with unchanged Python behaviour, including tuples, native scalar values, dict insertion order and warning delivery. A new Rust integration test compiles every document in `spec/vectors/` through the Rust API.
- **Query Spec Conformance Corpus, Compile Runner and Pack P0 (#253)**: defined the Query Spec conformance corpus layout (`spec/corpus/<pack>/<scenario>/`) with Draft 2020-12 schema validation (`spec/corpus/scenario.schema.json`), attribution notice (`spec/corpus/NOTICE`), and developer documentation (`spec/corpus/README.md`). Added the compilation test runner (`packages/python/tests/test_spec_corpus.py`) and automation recipes (`just corpus`, `just corpus-update` via `scripts/update_corpus.py`) validating multi-dialect compilation across openCypher, Apache AGE, ISO GQL, and SQL:2023 PGQ. Landed Pack P0 (`p0-match-return`) with 23 scenarios covering MATCH and RETURN basics (labels, multiple conjoined labels, inline property maps with literals and parameters, single-hop outgoing, incoming, and undirected relationships, edge types and variables, projections of nodes, relationships, and properties, column aliases, and literals) derived from the openCypher TCK.
- **Query Spec Corpus Live Execution and Engine Fixtures (#254)**: the conformance corpus now runs its scenarios on live engines. Added the engine-neutral fixture format (`spec/corpus/fixtures/<name>.json`, Draft 2020-12 `spec/corpus/fixture.schema.json`) and P0 setup graphs reproducing the cited TCK `Given a graph` / `having executed` blocks, referenced from each `scenario.json` by `fixture`. Added per-engine loaders in `packages/python/tests/spec_corpus_live_lib.py` that never use Voyager's write compilation: Neo4j and Memgraph through the `neo4j` driver with parameterized literal `CREATE`s, FalkorDB through its client, Apache AGE through `cypher()` in a dedicated graph, and PostgreSQL 19 through plain tables plus `CREATE PROPERTY GRAPH` in a dedicated schema. Every loader uses a dedicated graph/schema or a unique marker namespace, and drops it afterwards. `rows.json` records the reference rows from Neo4j, and `packages/python/tests/test_spec_corpus_live.py` compares every `supported` engine's rows against it, with the documented comparison rules for ordering, numbers, nulls, lists, maps, nodes and relationships (entity identity is not compared). Added `just corpus-live [engine]` (per-engine pass/fail/skip summary), `just corpus-record-rows [scenario...]`, and fixture validation in `just corpus` (`packages/python/tests/test_spec_corpus_fixtures.py`). Pack P0 passed live on Neo4j, Memgraph, FalkorDB, Apache AGE and PostgreSQL 19 for the targets marked `supported`; multi-label and whole-entity SQL/PGQ/AGE cases remain `known-diff` because of #285 and #286. `spec/corpus/README.md` documents fixtures, loaders, isolation, comparison rules, recording and live runs with `VOYAGER_TEST_HOST`.
- **Query Spec Corpus Pack P1: Filtering (#255)**: added `spec/corpus/p1-filtering/` with 25 scenarios covering the comparison operators (`=`, `<>`, `<`, `<=`, `>`, `>=`), boolean logic (`AND`, `OR`, `NOT`, `XOR`), `IN` with a literal list and with a parameter, `NOT` over `IN` and infix `NOT IN`, NULL handling and three-valued logic (`IS NULL`, `IS NOT NULL`, comparisons with null, `NOT` over null, null in `AND`/`OR`), the string predicates `STARTS WITH`, `ENDS WITH` and `CONTAINS`, and string/integer parameters. Each scenario has `scenario.json`, `query.spec.json`, all four expected compilation outputs and canonical `rows.json` recorded from Neo4j, with TCK feature/scenario citations where the shipped TCK subset matches. Added the shared `filter-persons` fixture. Targets that the current emitters cannot run live are recorded as `known-diff` with a reason: the cypher/AGE/GQL emitters write `!=` for `<>` (Neo4j, FalkorDB and AGE reject it) and infix `NOT IN` (Neo4j, Memgraph and AGE reject it), SQL/PGQ rejects `XOR`, the `IN` list form and the emitted `LIKE '%'` pattern. This ensures dictionary-based row decoding in `Session.execute()` preserves all projected column values on PostgreSQL 19 and DuckPGQ without key collisions.
- **ISO GQL path length (#362)**: the ISO GQL emitter now compiles `length(path)` to `path_length(path)` when its argument is a matched path variable (including an alias introduced by `WITH`), while `path_length(...)` keeps emitting `path_length(...)`. `length` on a string property or an argument whose kind is unknown still emits `char_length`, matching openCypher's legacy string-length meaning.
- **Native Apache AGE setup follows the Session (#354)**: a native Session with `dialect="age"` or an AGE graph name now runs `LOAD 'age'; SET search_path = ag_catalog, "$user", public;` on every PostgreSQL connection it opens, including pooled, reconnected and transaction connections, even when the URI has no AGE scheme or parameters; a non-AGE native Session leaves the connection untouched.
- **Memgraph Constraint DDL and Drop Parity (#335)**: For the Memgraph dialect, DDL generation (`SchemaManager.generate_ddl`, `generate_drop_ddl`, `create_all`, `drop_all`) and constraint DDL now emit native Memgraph un-named constraints (`CREATE CONSTRAINT ON (n:Label) ASSERT ...` / `DROP CONSTRAINT ON (n:Label) ASSERT ...`) instead of Neo4j named constraints, ensuring all constraints created by Voyager can be dropped by Voyager on Memgraph; relationship constraint emission safely no-ops as Memgraph does not support edge constraints; and idempotent re-execution of constraint and index DDL is safely handled.
- **A field declared with `= None` now has a real default (#333)**: `x: str | None = None`, `x: str = None` and `Field(default=None)` are equivalent, so `Field.has_default` is true, new instances fill `None`, and `export_schema` / `to_json_schema()` report `"default": null` instead of omitting the default. A value left at that default is absent rather than an explicit null on `CREATE`, `ON CREATE SET` and bulk create-only sets, never participates in a `MERGE` key, and is never overwritten by `ON MATCH SET`; a mixed bulk merge still writes the field only for rows that supply it. An explicit `obj.x = None` assignment after construction keeps its previous write behaviour.
- **Aggregate Null and Empty-Input Parity for Apache AGE and SQL/PGQ (#349)**: Apache AGE and SQL/PGQ aggregations now match openCypher null and empty-input semantics: `SUM` returns `0` over empty or all-null input via `COALESCE(SUM(x), 0)`, while SQL/PGQ `COLLECT` filters nulls and returns an empty list (`[]` on DuckPGQ, `'{}'` on PostgreSQL 19).
- **Apache AGE agtype decoding of nested entities (#350)**: `voyager_drivers::parse_agtype` now decodes vertices, edges and paths nested in lists and maps (such as the result of `COLLECT(n)`) and recognises them only by AGE's `::vertex`, `::edge` and `::path` annotations, so a plain map with `id`, `label` and `properties` keys or a list such as `[a, r, b]` is no longer mistaken for an entity or a path.
- **FalkorDB Native Parameter Encoding and Batched Writes (#339)**: Native FalkorDB sessions now recursively encode list and map parameters as Cypher literals instead of strings, route bulk ingestion through the native client, and ensure batched writes reflect actual database mutations and raise on failure.
- **SQL/PGQ property-graph DDL names tables and edge keys consistently (#325)**: **Breaking**. The generated `CREATE PROPERTY GRAPH` now names vertex tables after the node's primary label and edge tables after the relationship type, both folded to lower case and double-quoted, the same table names the SQL constraint and index DDL already used. Edge tables use distinct `src_<key>` and `dst_<key>` columns that reference the endpoint node's real key column, including for a self-relationship, and a relationship generated on its own resolves its endpoint node schema from the registry. Labels and property names are double-quoted in the property graph and in SQL/PGQ `IS` patterns (`LABEL "Person"`, `IS "Person"`), so PostgreSQL 19 matches their exact case; quoting is case-exact like Cypher, keeps mixed-case labels working, and makes reserved words such as `User`, `Order` and `Group` valid labels. DDL generated for a label whose class name differs from the label, a self-relationship, or an edge with a different destination key changes.
  - Migration, existing graphs: a graph created with the old unquoted mixed-case labels must be re-created with `DROP PROPERTY GRAPH <name>` followed by the `CREATE PROPERTY GRAPH` statement from `SchemaManager.generate_pgq_ddl(...)`. Tables and data are not touched, because `CREATE PROPERTY GRAPH` only describes existing tables.
  - Migration, existing tables: tables created from the old property-graph DDL used the model class name lower-cased (`<class name>`) and `<source label lower case>_id`/`<target label lower case>_id` endpoint columns, so rename or re-create them to `<label lower case>`/`<type lower case>` and `src_<key>`/`dst_<key>`. Old edge endpoint columns are renamed to `src_<key>`/`dst_<key>`; the vertex or edge table name changes only when its class name differs from its label or type. Tables created for the SQL constraint/index DDL already used the label/type names.
  - The SQLAlchemy bridge keeps its own metadata-driven table names and now quotes them.
- **SQL/PGQ ORDER BY Null Placement (#322)**: SQL/PGQ now emits `ASC NULLS LAST` and `DESC NULLS FIRST` for ORDER BY keys, ensuring DuckPGQ ordering matches Cypher and PostgreSQL 19 on keys that contain null values.
- **Query Spec: `ORDER BY` and `WHERE` under `DISTINCT` or an aggregation may repeat a projected expression**, as Neo4j allows.
  - Accepted now: `RETURN DISTINCT p.city ORDER BY p.city`, `ORDER BY p.city + 1`, `RETURN COUNT(p) AS c ORDER BY count(p)`, and the same forms in a `WITH`'s own `order_by` and `where`.
  - Still rejected: a variable that is not projected, such as `ORDER BY p.age`.
  - The fluent scope check accepts the same cases.
- **Fluent queries check variable scope before compiling (#287)**: **Breaking** for fluent code that used to build statements referring to undefined variables. `QueryBuilder::try_build` now runs an AST-level scope check with the same rules as the Query Spec consumer, so a fluent query raises `VoyagerError` with code `INVALID_CLAUSE` naming the variable and the clause instead of emitting a statement the server rejects. A `WITH` keeps only the names it projects, its own `WHERE`/`ORDER BY` also see the names in scope before it unless it is `DISTINCT` or contains an aggregation, and a following mutation or `RETURN` sees only the projected names. Root `ORDER BY` sees the names `RETURN` projects plus the pre-`RETURN` scope unless the `RETURN` is `DISTINCT` or aggregates; an `ORDER BY` that repeats a projected expression (for example `RETURN DISTINCT p.city ORDER BY p.city`) still compiles. Subquery, pattern-comprehension and list-comprehension variables stay local while correlated references to outer variables are allowed, and variables introduced by `CREATE`/`MERGE` are visible to later mutations and `RETURN`. A non-`DISTINCT`, non-aggregating `WITH ... WHERE` on a variable from before the `WITH` still compiles. Bare raw-string projections and bare identifiers passed to functions are treated as opaque and are never rejected. `QueryBuilder::build` remains the unchecked fragment entry point used for nested subqueries, which are checked against their enclosing scope by `try_build`. New `packages/python/tests/test_fluent_scope.py` mirrors the spec scope cases, and Rust unit tests cover the same rules.
- **Relationship Endpoints and Optional Field Types in the Schema Registry (#125)**: relationship endpoints declared with `source_node`/`target_node`/`source_labels`/`target_labels` now reach the model and the registry. Previously these class keywords raised `TypeError`. A class-body `__source_labels__`/`__target_labels__`/`__direction__` is honoured when no keyword is given. Fields annotated `Optional[T]` or `T | None` now register with the type of `T` instead of `OPTIONAL` or `ANY`, which also corrects their type in generated graph-type DDL.
- **Query Spec v1 rejects references the clause emission order cannot honour (#271)**: **Breaking** for specs that used to compile into statements referring to undefined variables. The consumer now checks variable scope in its fixed emission order (`load_csv`, `unwinds`, `matches`, `linear_clauses`, `with_clauses`, `mutations`, then `RETURN`), so a linear `filter`/`let` can no longer read a name a later `WITH` defines, and a mutation or `RETURN` can no longer use a name the last `WITH` did not project. A `WITH` replaces scope with exactly the names it projects: an unaliased bare variable keeps that variable, and every aliased projection keeps only its alias, so `load_csv`, `unwinds`, match and `let` names are dropped unless the `WITH` projects them. A `WITH`'s own `where` and `order_by` also see the names in scope before the `WITH`, unless the clause is `DISTINCT` or contains an aggregation, in which case they see only the projected names and a pre-`WITH` reference raises `INVALID_SPEC` with the message `a WITH with DISTINCT or an aggregation only exposes the names it projects`; root `order_by` follows the same rule for a `DISTINCT` or aggregating `RETURN`. Such a spec raises `VoyagerError` with code `INVALID_SPEC` and the identifier's JSON Pointer, and the message names the variable and says which clause order rule it breaks (for example `variable 'n' is not in scope here: linear clauses are emitted before WITH clauses; move the reference into with_clauses[0].where`). A `WITH` projection that is not a bare variable now also requires an alias in both the spec consumer and the fluent API: an unaliased `WITH p.name` raises `INVALID_SPEC` at the projection item's pointer, or `VoyagerError` with code `INVALID_CLAUSE` from fluent compilation, with a message such as "WITH projection 'p.name' needs an alias (for example 'p.name AS name'); only a bare variable may be projected without one". Parameters and literals are unaffected, subquery and comprehension variables stay local, `RETURN` projections still work without aliases, and `spec/README.md` documents the emission order and strict replacement scope with examples. New invalid vectors and `packages/python/tests/test_spec_scope.py` cover the #271 reproduction, the corrected `with_clauses[i].where` form, dropped mutation targets, dropped LOAD CSV and unwind names, the alias rule and each variable position.
- **Query Spec v1 Path Steps No Longer Drop Extra Items Silently (#187)**: a node step accepts only `[node, variable, labels, properties?]` and an edge step only `[edge, direction, types, variable?, min_hops?, max_hops?, properties?]` (the optional properties item is #263); a non-null item past that shape (for example a 5th node item or an 8th edge item) now raises `INVALID_SPEC` at its path instead of being ignored. Trailing `null` items are still accepted. Edge steps also accept the schema's short form `[edge, direction, types]`, with the variable, hop bounds and properties defaulting to `null`.
- **Query Spec v1 `where` Accepts a Single Expression or a Predicate List (#187)**: `matches[i].where` and `with_clauses[i].where` now accept the schema's single-expression form, for example `"where": ["bin", "=", ["prop", "p", "age"], ["lit", 21]]`, which previously failed because every JSON array was treated as a list of predicates. A `where` array whose first element is a string is one expression; one whose first element is an array or object is a list of expressions; an empty array is an empty predicate list. The two forms compile to identical Cypher. Error messages now name JSON types (`string`, `number`, `array`, ...) instead of Python type reprs such as `<class 'int'>`, and expression-position rejections suggest `["lit", value]` for scalars or `["lit", [...]]` / `["list", [...]]` for lists. Raw JSON value positions (`load_csv`, path steps, mutation and projection fields, pagination, enums, `["lit", value]` payloads, comprehension filters, and subquery specs) are unchanged.
- **Query Spec v1 Accepts JSON Arrays at Every Position (#185)**:
  - The spec consumer now accepts Python lists (the JSON array form produced by `json.loads`/`json.dumps`) and Python tuples interchangeably at every array position, so any schema-valid JSON document compiles instead of raising `TypeError: 'list' object is not an instance of 'tuple'`.
  - Fixed list-rejected positions: `load_csv`, `unwinds` entries, `case` branches, merge `ON CREATE SET` / `ON MATCH SET` entries, `order_by` entries (root and inside `with_clauses`), `linear_clauses` entries, path steps, mutations and projections.
  - Fixed tuple-rejected positions for uniformity: `fn` arguments, `case` branch lists, `list` literal items, and the array containers `matches`, `paths`, `unwinds`, `mutations`, `with_clauses`, `projections`, `order_by`, merge set lists and `linear_clauses`.
  - Malformed shapes at these positions (non-sequences and too-short arrays) now raise `VoyagerError` with code `INVALID_SPEC` naming the field, instead of bare `TypeError`/`IndexError` from the FFI layer.
  - `order_by` direction accepts a boolean (`true` = ascending, `false` = descending) or the uppercase strings `"ASC"`/`"DESC"`, for both the `[variable, property, direction]` and `[expression, direction]` entry variants; the schema documents both forms. Other spellings (for example `"asc"`, `"up"` or `1`) raise `INVALID_SPEC`, and an `['alias', expr, name]` projection now keeps its alias in the JSON list spelling, matching the tuple spelling.
- **Query Spec v1 Enforces Exact Shapes and Build Failures (#187)**: every fixed-arity position now rejects items past its documented shape with `INVALID_SPEC` at the extra item's path, covering `load_csv`, `unwinds` entries, every mutation tag, every projection tag, `order_by` entries, `linear_clauses` entries, merge `ON CREATE SET`/`ON MATCH SET` entries, `case` branches and every expression tag; path steps keep their trailing-`null` tolerance. A non-string `["alias", expr, name]` name, an empty `["prop", "", property]` variable, an empty `["ident", ""]`/`["param", ""]` name, and an object in an expression position without an `expr` key are rejected with their JSON path. `pattern_comp` path specs and `exists`/`count` subquery specs accept tuples as well as lists. One leading `$` is stripped from `unwinds` parameter names and `["param", name]`, so `["$batch", "row"]` emits `UNWIND $batch AS row`. Build and emitter failures from `compile_query_from_spec` now raise `VoyagerError` with `INVALID_SPEC` at the document root (or the core `UNSUPPORTED_FEATURE`/`UNSUPPORTED_DIALECT` code) and messages name the AST node kind instead of a Rust debug dump; messages no longer use Python `repr`, and a non-string object key reports at the containing object's path. `spec/README.md` now documents `linear_clauses`, every accepted edge-direction spelling, the full operator/aggregate tables, dialect aliases and per-dialect gaps, and its JSON examples are compiled by a test in all four dialects.

- **SQL/PGQ ORDER BY on expressions outside GRAPH_TABLE (#319)**: ordering expressions that are not returned columns are now evaluated inside `GRAPH_TABLE` `COLUMNS` under an internal alias and selected only as returned columns in the outer query, so pattern variables are in scope on PostgreSQL 19 and DuckPGQ.
- **SQL/PGQ ORDER BY on non-returned properties (#320)**: ordering by a property that is not projected now exposes it in `GRAPH_TABLE` `COLUMNS` under an internal alias, avoiding missing-column errors in the outer query on PostgreSQL 19 and DuckPGQ.

## [0.4.2] - 2026-11-22

### Fixed
- **SQL/PGQ parameter binding in Python bridges (#226)**: `PostgresBridge._format_pgq_statement` now binds `GRAPH_TABLE` parameters positionally as `%s` placeholders like standard SQL instead of interpolating parameter values directly into the SQL statement, supporting prepared statements, duplicate parameter names, and preventing injection from hostile values. `DuckDbBridge` safely encodes values for `GRAPH_TABLE` queries as typed SQL literals (strings with quote-doubling, ints, floats including `'nan'::DOUBLE` / `'inf'::DOUBLE`, booleans, `NULL`, dates, datetimes, times, lists, and maps) and raises `TypeError` for unsupported parameter types, working around DuckPGQ's lack of prepared parameter support inside table function ASTs.
- **Native PostgreSQL list parameter encoding (#283)**: `prepare_postgres_statement` and `value_to_text` in the native PostgreSQL driver now encode JSON array parameters as PostgreSQL array literal text (`{elem,elem}`) with double-quoting and backslash-escaping for strings, `NULL` for null elements, nested arrays, unquoted numbers and booleans, and quoted JSON text for nested maps, instead of sending JSON text (`[...]`). This enables list parameters to be bound where PostgreSQL expects an array (such as `= ANY($1)` or array columns in plain SQL and `GRAPH_TABLE`), matching the behaviour of the `psycopg` bridge while preserving JSON encoding for top-level maps and Apache AGE parameter maps.
- **Apache AGE queries returning several nodes or relationships (#285)**: the AGE column definition list repeated `entity` for every whole node or relationship (`AS (entity agtype, entity agtype, ...)`), so PostgreSQL rejected the query with `column name "entity" specified more than once`. When a query returns several whole nodes or relationships, their columns are now named after the returned variables (`AS (a agtype, r agtype, b agtype)`), and any repeated column name gets a numeric suffix (`name`, `name_1`, ...). A query returning a single whole node or relationship still keys it `entity`, so code reading `row["entity"]` keeps working.
- **Compile-time validation of unsupported pattern and column constructs (#286)**: `AgeEmitter` and `SqlPgqEmitter` (shared by DuckPGQ) now reject unsupported graph patterns and projections at compile time with `UnsupportedFeature` across both the fluent builder and `compile_query_from_spec`: Apache AGE rejects node patterns with multiple labels and relationship patterns with alternative types, while SQL/PGQ rejects node patterns with multiple labels (conjunction), node and relationship expressions using negation, conjunction, grouping, or wildcard, and whole node or relationship variables in the `COLUMNS` clause. Valid single-label node patterns, node label disjunction (`IS A | B`), SQL/PGQ relationship type alternation (`-[r IS KNOWS | HATES]->`), and property column projections remain supported and unchanged.
- **`Query.set()` no longer drops arguments silently (#295)**: `set()`, `on_create_set()` and `on_match_set()` skipped arguments they did not recognise, so the query was compiled without the `SET` and the write never happened. They now raise `VoyagerError` (`INVALID_CLAUSE`) for:
  - keyword arguments without a variable prefix (`city="Berlin"`, `p={"city": "Berlin"}`) or with an empty part (`"p."`, `".city"`);
  - positional values that are not an assignment such as `p.city == value` or a `Node`. This includes comparisons such as `p.city > 10`, which were written as `SET p.city = 10`.
  
  Code passing such arguments now gets an error instead of a query without the `SET`. The supported forms compile as before, and a `Node` with no changed fields is still a no-op. `on_create_set()` / `on_match_set()` also accept a `Node` with changed fields, like `set()`.
- **Inequality compiles to `<>` (#301)**: `neq`, `ne`, `!=` and `<>` inputs now emit `<>` instead of `!=` on Cypher, Apache AGE, ISO GQL and SQL/PGQ, so Neo4j, FalkorDB and Apache AGE accept the statement.
- **`not_in` compiles to `NOT (x IN list)` (#302)**: `.not_in(...)` and Query Spec `not_in` now emit `NOT (x IN list)` on Cypher, Apache AGE and ISO GQL; SQL/PGQ keeps infix `NOT IN` for now (#303).

### Security
- **`url` updated to 2.5.9 (RUSTSEC-2026-0592)**: `url` 2.5.8 and earlier can overflow the stack in `Url::origin()` on nested `blob:` URLs. Voyager does not call `Url::origin()`; the update clears the advisory for builds that use the lockfile.

- **Breaking:** `session.transaction()` is now a real database transaction, and the in-memory API is `UnitOfWork` / `unit_of_work()` (#177):
  - `session.transaction()` / `async with session.transaction()` begins a real `BEGIN`/`COMMIT`/`ROLLBACK` transaction on Neo4j, Memgraph, and Apache AGE/PostgreSQL through both the Python driver bridges and the native Rust client, and on the embedded DuckDB/DuckPGQ and Relate bridges. Every session execution path (`execute`, `execute_to_polars`, `execute_to_arrow`, `run_bulk`, `flush()`) is routed through the active transaction; a clean exit commits, an exception rolls back and re-raises, and nested transactions raise.

### Fixed
- **Native PostgreSQL and Apache AGE Parameter Binding (#222)**:
  - The native PostgreSQL client now binds parameters through the extended query protocol (`Parse` / `Bind` / `Describe` / `Execute` / `Sync`) instead of substituting values into SQL text; parameter values are never interpolated for any dialect.
  - Apache AGE statements bind the `%s` agtype parameter map as positional parameter `$1`, while `$name` references inside the `$$ ... $$` Cypher body are left for AGE to resolve from that map.
  - SQL and SQL/PGQ `$name` placeholders are rewritten to positional `$1`, `$2`, ... in first-appearance order, with repeated names reusing one bound value.
  - Error responses during the extended flow are drained through `ReadyForQuery`, so the connection stays usable and a failed statement inside `BEGIN` reports `FailedTransaction`.
  - Apache AGE bulk `UNWIND $batch` statements now include the third `cypher()` parameter argument even when the batch map is a runtime parameter, so bulk create, bulk upsert, and identity-map flushes work on AGE.
- **CI runs once per opened PR and once per push (CI)**: label and other PR metadata changes no longer trigger CI. The `full-ci` and `skip-changelog` labels are read from the PR at run time instead of from the event payload, so labels attached right after opening are honoured and a manual re-run picks up a label added later. Opening a PR with several labels previously started one run per label; cancelled runs posted a failing `CI Gate` that could leave the PR blocked.
- **PostgreSQL and AGE URI Graph Parameters (#221)**:
  - `create_bridge()` now removes `?graph=` and `?graph_name=` from the connection string before calling `psycopg.connect()` on both the sync and async paths, so real PostgreSQL and `age://` URIs no longer fail with `psycopg.ProgrammingError: invalid URI query parameter`. Every other query parameter is kept unchanged and in order.
  - Graph selection precedence is unchanged: an explicit `graph_name` argument wins over the URI parameter, and `?graph=` wins over `?graph_name=`.
  - The native URI parser no longer treats `?graph=` as the PostgreSQL database name in the startup message; Apache AGE graphs live inside the connected catalog, and `?graph_name=` now also triggers AGE initialization. Redis/FalkorDB `?graph=` continues to select the graph database.
  - `VoyagerError.skipped` is now a declared `list[str]` attribute that exists (empty by default) on every `VoyagerError`, so callers no longer need `getattr(error, "skipped", ...)`.
- **Relationship Unique and Primary-Key Constraint DDL (#211)**:
  - On the Cypher dialect, relationship fields marked `unique=True` or `primary_key=True` now emit a `REQUIRE r.<prop> IS UNIQUE` constraint instead of only an existence constraint, so duplicate values are rejected.
  - Relationship existence (`REQUIRE r.<prop> IS NOT NULL`) constraints are now emitted only when the field is non-nullable, so a nullable unique relationship field is no longer made mandatory.
  - Every emitted relationship constraint now has a matching `DROP CONSTRAINT ... IF EXISTS` statement, using the `unique` and `not_null` kinds of `cypher_rel_constraint_name`.
  - Relationship secondary indexes are still skipped for unique and primary-key fields, since the uniqueness constraint provides its own index.
  - Constraint DDL now emits a field's `UNIQUE` statement before its `NOT NULL` (existence) statement; when Neo4j Community rejects Enterprise-only constraints, the remaining constraints still run and one `VoyagerError` (`SCHEMA_ERROR`) reports every skipped statement after confirming the others were applied.
- **FalkorDB Full-Text Index DDL Syntax and Idempotency (#198)**:
  - Updated FalkorDB full-text index creation and drop DDL emitters to use native declarative Cypher syntax accepted by FalkorDB 6.0.4+: `CREATE FULLTEXT INDEX FOR (n:<label>) ON (n.<prop1>, n.<prop2>)` and `DROP FULLTEXT INDEX FOR (n:<label>) ON (n.<prop1>, n.<prop2>)` for nodes, and `CREATE FULLTEXT INDEX FOR ()-[r:<type>]-() ON (r.<prop1>, ...)` and `DROP FULLTEXT INDEX FOR ()-[r:<type>]-() ON (r.<prop1>, ...)` for relationships.
  - Replaced obsolete procedure calls `CALL db.idx.fulltext.createNodeIndex(...)` and `CALL db.idx.fulltext.drop(...)` which were rejected by FalkorDB 6.0.4.
  - Extended FalkorDB bridge and connection error handling to treat "already indexed" and "no such index" response errors as idempotent successes on `CREATE/DROP FULLTEXT INDEX` and `CREATE/DROP VECTOR INDEX` statements, ensuring `session.create_indexes()` and `session.drop_indexes()` can be called repeatedly without raising.

  - Made the Apache AGE graph name configurable on `Session` and `AsyncSession` via `graph_name="custom_graph"`.
  - Added support for `graph_name` on `PostgresBridge`, `AsyncPostgresBridge`, and URI query strings (`?graph=...` / `?graph_name=...`) parsed by `create_bridge()`.

  - Default factories are evaluated per instance instead of once at class definition, so mutable defaults such as lists are never shared between instances.
  - Declaring both `default` and `default_factory` now raises `TypeError` when the field is created.
  - Defaults flow through `Query.create`, bulk create plans, identity-map flushes, and `Node.save()`. In `Query.merge` and bulk merge plans they are written only in `ON CREATE SET` for the records that defaulted them, never in the MERGE key or `ON MATCH SET`, so an existing node keeps its stored value. Read applied values with `Node.get()` / `Relationship.get()`; instance attributes remain bound fields for the query DSL.
- **Partial Bulk MERGE and Dirty-Field Flush Writes (#205)**:
  - Bulk MERGE plans now write only the properties each row actually supplies on `ON CREATE SET` and `ON MATCH SET`; an omitted property keeps its stored value, while a property supplied as `null` explicitly clears it.
  - Records are grouped by both the properties they supply and any fields filled from a declared default. Each group gets its own compiled statement (`BulkIngestionPlan.batch_statements` / `BulkIngestionBatch.statement`), which every bridge, transaction, and session bulk executor now runs per batch. Default-filled fields stay create-only, and every group compiles with the session's configured graph name.
  - `Session.flush()` / `AsyncSession.flush()` and `Node.save()` / `Node.async_save()` now update only dirty fields instead of nulling every untouched property, while new records still send their default-filled fields as create-only.
  - For Polars, PyArrow, and pandas inputs, every column present in the frame counts as supplied, so a null cell clears that property; columns absent from the frame are not written.
- **Bolt URI Embedded Credentials Stripping and Decoding (#181)**:
  - `create_bridge()` now extracts and URL-decodes user and password credentials from Bolt connection URIs, forwarding them as `auth=(user, password)` to `GraphDatabase.driver` / `AsyncGraphDatabase.driver`.
  - Strips `userinfo` from the netloc so the Bolt driver receives a clean `scheme://host:port` string; query parameters are parsed into driver options and removed from the URI, because direct `bolt://` drivers reject them.
  - Added password masking (`user:***@host`) across all connection exception and log formatting paths to guarantee secrets are never leaked.
- **Apache AGE Connection Setup and Scheme Rewriting (#191)**:
  - `create_bridge()` now rewrites `age://` and `age+s://` URI schemes to `postgresql://` prior to connecting, mapping `+s` and `+ssc` to `sslmode=require`.
  - Added unified `setup_postgres_age()` connection initializer that runs `LOAD 'age'; SET search_path = ag_catalog, "$user", public;` unconditionally for `age://` schemes and automatically when the `age` extension is detected in `pg_extension` for `postgresql://` connections.
  - `PostgresBridge` and `AsyncPostgresBridge` now auto-detect AGE on user-supplied connections, allowing `Session(PostgresBridge(conn), dialect="age")` to execute AGE Cypher queries out of the box.
- **Node `__label__` Single-Label Alias (#180)**:
  - `Node` subclasses now accept `__label__ = "X"` as the single-label form of `__labels__ = ["X"]`, and the label is used consistently by query compilation, cached labels, schema registration, and bulk ingestion.
  - Declaring both `__label__` and `__labels__` with a different primary label now raises `TypeError` at class creation.
  - An explicit `@node("X")` decorator argument takes precedence over class-body label declarations; `Relationship` classes now honour a class-body `__type__` in the same way.
- **Live-Engine Python Tests Missing the `live` Marker (#199)**:
  - Marked the remaining Neo4j/Memgraph/FalkorDB and openCypher/openGQL Tier 3 integration tests with `@pytest.mark.live` so `pytest -m "not live"` no longer runs them when containers are up.
  - Existing `skipif` port probes are kept, so `pytest -m live` still skips cleanly when a container is unavailable.
  - `create_bridge()` auth tests that need `psycopg` or `falkordb` are skipped when those optional drivers are not installed (they are not installed on Python 3.14), fixing the Python 3.14 jobs on `main`.
- **Identity Map Uses the Declared Primary Key (#178)**:
  - `Session.register()` / `AsyncSession.register()`, `flush()`, `Node.save()`, and `Node.async_save()` now default `key_field` to the model's declared `Field(primary_key=True)` property instead of assuming `id`, falling back to `id` only when the model declares no primary key.
  - Explicit `key_field=` arguments continue to override the detected primary key unchanged.
- **OGM Write Path and Class-Level Field Binding (#174, #175, #176)**:
  - `Query.create(instance)` now inlines every set field as parameterised pattern properties (nodes and relationships); previously all property values were silently dropped.
  - `Query.merge(instance)` keys the MERGE pattern on the primary key (else unique fields, else all set fields) and writes the remaining fields to both `ON CREATE SET` and `ON MATCH SET`.
  - `Query.merge(...).where(...)` folds equality predicates into the MERGE pattern and raises `ValueError` for any other predicate instead of dropping it, which produced a keyless MERGE.
  - Class-level fields such as `Person.name` resolve to the alias of the single pattern created from that class in `return_`, `where`, `order_by`, `with_`, `set` and aggregations, instead of emitting `RETURN .name` or `WHERE $p0`; an ambiguous or missing pattern raises `ValueError`.
  - Apache AGE: `cypher()` query parameters are passed as a single JSON argument.
- **Stack Overflow in Recursion Depth Guards on Windows and macOS (#166)**:
  - Shrank the per-level stack frames of the RESP parser (`parse_resp_slice`) and the Python AST converter (`py_to_node_handle_depth`) by moving match arms into small helpers, so depth guards trigger before the stack is exhausted on 1 MB (Windows) and 2 MiB (macOS) stacks.
  - Lowered `MAX_RESP_DEPTH` from 128 to 64, matching `MAX_PACKSTREAM_DEPTH`.
  - Enabled `opt-level = 1` in the dev profile for `voyager-drivers` and `voyager-pyo3`.
  - Depth-guard tests now run on an explicit 1 MB stack on every platform.
- **Panic Safety on Malformed and Non-ASCII Inputs (#158)**:
  - Eliminated panics on malformed query topologies (such as incomplete `MATCH (`, `MATCH (n)-[`, and `MATCH (n)-[r]->(`) by parsing in byte space with bounds-checked Unicode helpers.
  - Hardened `agtype` string cleaning in `voyager-drivers` to be UTF-8 safe across multi-byte inputs.
  - Replaced reachable `unreachable!()` arms in connection pool drop and handover routines with recovery and warnings.
  - Replaced `unreachable!()` arms in DDL emitters with explicit `UnsupportedDialect` errors.
