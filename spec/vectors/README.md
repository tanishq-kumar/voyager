# Query Spec v1 reference vectors

These vectors pin the behaviour of `spec/query_spec.v1.schema.json` and of the
native Query Spec v1 consumer behind `compile_query_from_spec` (issue #188).
Every `expected` value in `valid/` was generated by compiling the same spec with
the real compiler and then reviewed, so it records the actual statement and
parameters each emitter produces rather than a hand-written guess.

## Layout

- `valid/*.json` — a valid Query Spec v1 document.
- `invalid/*.json` — a document the consumer rejects with `INVALID_SPEC`.

Each file is a JSON object:

```json
{
  "description": "What the vector exercises.",
  "spec": { "spec_version": 1, "...": "..." },
  "expected": { "...": "..." }
}
```

## Valid vectors

`expected` maps each dialect key to either a successful compilation or the
error code that dialect raises because it does not support the construct:

```json
{
  "cypher":   { "statement": "MATCH (p:Person) RETURN p.name", "parameters": {} },
  "age":      { "statement": "SELECT * FROM cypher(...)", "parameters": {} },
  "iso_gql":  { "statement": "MATCH (p:Person) RETURN p.name", "parameters": {} },
  "sql_pgq":  { "statement": "SELECT * FROM GRAPH_TABLE (...)", "parameters": {} },
  "duck_pgq": { "statement": "SELECT * FROM GRAPH_TABLE (...)", "parameters": {} }
}
```

An unsupported construct is recorded as `{"error": "<VoyagerError code>"}`, for
example `{"error": "UNSUPPORTED_FEATURE"}`. The harness maps `duck_pgq` to the
consumer's `duckpgq` dialect alias; the other four keys are consumer dialect
names.

## Invalid vectors

`expected` records the `INVALID_SPEC` error and its JSON Pointer:

```json
{
  "description": "The 'literal' alias for 'lit' is not a canonical tag.",
  "spec": { "spec_version": 1, "...": "..." },
  "schema_valid": false,
  "expected": { "error": "INVALID_SPEC", "path": "/projections/0/1" }
}
```

`schema_valid` is the result of validating `spec` against the JSON Schema:
`true` means the schema alone accepts the document, so only the consumer
rejects it (for example an empty spec or both `skip` and `offset`). `false`
means the schema already rejects it.

The Python harness is `packages/python/tests/test_spec_vectors.py`; run it with
`just spec-check`.
